# 항만 디지털 트윈 데모

좌측은 대상 탐색, 중앙은 3D 위치 확인, 상단 모니터링은 전체 운영 현황을 담당합니다.

## 좌측 메뉴

- 터미널: 블록 / 컨테이너 / 선석
- 스케줄: 입출항 목록 → 기항별 타임라인·잔여 작업·계획 및 예상 이안 → 선박 상세
- 선박: 선박 목록·현재 상태 → 제원·작업 정보·위치 추적·그래프
- 장비: 안벽 크레인 / 오버헤드 크레인 → 상태·상세·그래프

현재 모델에는 터미널별 소속 데이터가 없어 전체를 `데모 터미널` 하나로 표시합니다. 블록·컨테이너·선석은 같은 모델 범위를 조회합니다.

스케줄과 선박은 3D 옆의 좁은 패널로 열립니다. 좌측 메뉴를 다시 누르거나 Escape를 누르면 패널을 닫을 수 있습니다.

## 운영 시나리오

상단 모니터링 → `운영 시나리오`에서 정상 운영·도선 지연·기상 제한을 선택합니다. 기본 모니터링 탭은 개요입니다.

- 도선 지연: 1선석의 출항 준비시간 90분 증가
- 기상 제한: 1선석의 출항 준비시간 180분 증가
- +1시간: 운영 시각 수동 이동
- 데모 초기화: 시나리오와 수동 시간 이동 초기화. 관제 시계는 계속 흐릅니다.

## 데이터 구성

- `constants/portCall.ts`: 시나리오와 단계별 시간 설정
- `domain/portCall.ts`: 기항 상태와 누적 작업량 계산
- `domain/portSim.ts`: 기존 선박·크레인 데이터에 일정과 선석 상태 결합
- `stores/usePortCallStore.ts`: 선택 시나리오와 수동 시간 이동
- `ship/ScheduleContent.tsx`: 좌측 스케줄 목록과 기항별 상세
- `terminal/BerthContent.tsx`: 선석별 점유 상태와 배정 선박
- `monitoring/PortCallTab.tsx`: 모니터링 내 운영 시나리오

## 데모 범위

실제 항만 데이터와 연동하지 않습니다. 타임라인은 모의 시계 기준이며 실제 이벤트 수신 여부가 아닙니다.

시나리오 선택은 전체 모의 일정을 다시 계산합니다. 운항 중 발생하는 지연의 이력 누적, 서로 다른 선박의 복수 예약, 선석 재배정은 포함하지 않습니다. 선석별 선박은 기존 모델을 반복 사용합니다.

3D 이동·화물 애니메이션은 기존 재생 흐름을 유지하며 운영 시각 이동과 동기화하지 않습니다. 기존 장비 고장은 생산성 표시에 반영되지만 작업 완료량은 계획 생산성에 따른 모의값입니다.

후속 접안 영향은 다음 예약시각과 이안 후 선석 정리시간으로 계산합니다. 선석 여유시간 안에서 흡수되는 지연은 영향이 0분으로 표시됩니다.

## 검증

`node --test scripts/portCall.test.mjs`로 단계 전환, 출항 지원 지연, 기항 경계의 누적 작업량을 검증합니다.
